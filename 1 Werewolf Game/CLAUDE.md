# WearwolfeGame — project context

A Werewolf game where 5–10 seats are played by different AI models competing against each other. Any seat can be set to human before the game starts, and several humans are allowed. The interface must be slick and make game progress easy to follow.

## Working rules (from the owner — always follow)
- **Never start a step without the owner's explicit confirmation.** At the end of every step, report (1) what was done and (2) what the proposed next step is, then stop and wait.
- Keep all project files and context inside this folder.
- Quality gate: each major deliverable is scored by a separate, independent evaluator agent. Fix what it finds and re-evaluate until it reaches **9/10 or higher**. The owner then confirms before we move on.
- If an architecture or design question is unclear, ask the owner instead of guessing.

## Owner decisions
- **Game:** 5–10 seats, and a model may fill several seats. The Seer sees alignment only (wolf / not wolf). Roles are fully revealed on death. The Angel ends the game immediately when it wins. Multiple humans are allowed. There is an optional post-game debrief that needs host approval; it is just for fun and nothing carries into the next game.
- **Tech:**
  - TypeScript/Node end to end.
  - The server runs on the owner's PC, and humans join over the LAN.
  - SQLite storage.
  - Every model is reached through OpenRouter with one API key.
  - A configurable per-game cost cap that pauses the game.
  - Settings live in config files; the UI shows only the lobby essentials.
  - The web UI is built later against `client-sdk`.
